# CalorieK v0.0.2：Windows 使用说明草案

面向 Windows 10/11 x64 用户。应用本地、离线运行；打包版不需要安装 Python。v0.0.2 目前仅准备源码，尚待审核和 Windows 独立验证，本文不表示已经打包或发布。实际可下载版本以 [GitHub Releases](https://github.com/AtticusPhu/CalorieK/releases) 为准。

## 下载与首次启动

1. 在实际已发布 Release 的 Assets 中下载对应版本的 Windows x64 ZIP。没有资产则说明尚未提供此版 Windows 程序；`Source code (zip)` 不是打包应用。旧版 v0.0.1 不包含每日营养卡片。
2. 解压全部内容，保留 `CalorieK` 文件夹的完整结构，包括 `CalorieK.exe`、`_internal` 及其他随包文件。不要在 ZIP 内直接运行，也不要将 EXE 单独拖出。
3. 双击 `CalorieK.exe`，按向导填写个人资料和当前实际体重。之后从首页记录饮食、运动和称重。
4. 在“设置与数据”中选择 kJ 或 kcal 并保存。新用户、从旧库升级的用户默认使用 kJ；切换只改变显示/输入单位。

若 Windows 提示未知发布者或阻止启动，先核对下载来源及该 Release 提供的校验信息；不要关闭系统安全保护或下载来历不明的 DLL。程序启动失败时先保留错误提示，按下方排查。

## 数据在什么位置

默认主库：

```text
%LOCALAPPDATA%\CalorieK\data\caloriek.sqlite3
```

可把 `%LOCALAPPDATA%\CalorieK` 粘贴到资源管理器地址栏打开。`data\backups` 保存自动安全备份，`config.json` 保存设置页选择的目录偏好。程序解压目录不是数据目录，删除旧程序目录也不会自动删除默认用户数据。

数据目录优先级：命令行 `--data-dir` → 环境变量 `CALORIEK_DATA_DIR` → 保存的目录偏好 → 默认目录。高级用户可从 PowerShell 指定本次启动路径，例如：

```powershell
& "D:\Apps\CalorieK\CalorieK.exe" --data-dir "D:\CalorieKData"
```

持久切换目录请用设置页选择空目录并保存。程序复制数据库到新目录，保留原库；下次启动仍会优先采用现存命令行/环境变量覆盖，所以更改设置后应留意是否还有这些覆盖。

数据库、备份 ZIP 和导出 JSON 含有健康记录，目前不加密。请放在受保护的本机位置；应用不会自动上传或替你建立云端备份。

## 升级、schema v3 与恢复

- 更新程序前，先在设置页创建 ZIP 备份并保存到安全位置；关闭其他 CalorieK 实例，再解压新程序到独立文件夹运行。保留旧程序与备份，直到新版本验证完成。
- v0.0.1 使用 schema v2；v0.0.2 使用 schema v3，增量追加营养字段，不更改旧记录、能量、体重、时间戳、偏好或派生缓存。新字段保持未知，不猜测历史营养。
- 有效 v2 库升级前生成 `data\backups\pre_migration_v2_to_v3_*.sqlite3`；v1 库先生成 `pre_migration_v1_to_v2_*.sqlite3`，沿用能量迁移后追加 v3。自定义数据目录的快照位于其 `backups` 下。
- 迁移前快照包括已提交的 WAL 内容，保持原 schema 和数据/单位，是独立 SQLite 文件。快照失败不执行迁移，迁移失败回滚并保留快照。再次打开不会重复升级或重复转换能量。
- 比 schema v3 更新或结构损坏/不完整的数据库会被拒绝。不要强改 schema 标记；**v0.0.1 不应打开已升级的 v3 库**。需要回退时先停止使用并保留新数据，再依审核方案用升级前备份恢复，避免丢失升级后的记录。
- 设置页“从备份恢复”支持合法的 v1/v2/v3 **ZIP 备份**。在隔离候选库中完成迁移与校验，准备替换文件后为当前库创建 `backups\pre_restore_*.zip`，最后替换；源 ZIP 不变。其他程序占用数据库时可能安全失败；关闭其他实例后再处理。
- 恢复使用当前数据目录，不会自动采用 ZIP 中记录的原电脑路径。JSON 导出是查看/分析格式，当前没有 JSON 导入功能。
- 原始迁移快照 `.sqlite3` 不等于应用 ZIP 备份，不能直接通过 ZIP 恢复菜单使用。发生异常时保留整个数据目录、快照和错误信息，再按审核后的方案恢复；不要自行删除 WAL/SHM 或覆盖仍在使用的数据库。

## 每日营养

- 食品编辑器按每 100g 单独填写四项营养；未勾选“已知”为未知，勾选后 `0.00` 表示已知为零。旧版字段仍保留，不自动推断成新的营养值。
- 新摄入保存当时快照；后来修改食品或食谱不改变历史。显示两位小数不会降低已保存或计算值的精度。
- 首页营养卡片可选择历史日期，仅影响营养卡片，不改变今天的能量和体重图表。
- 缺少任何摄入的营养数据时显示 **部分记录无营养数据**；数字只是已知部分合计。历史记录不会回填；全部未知显示“未知”，无记录显示 `0.00 g` 并注明没有记录。
- ml 不等于 g。当前没有密度字段，体积食品无法按质量换算营养，保持未知；原来的能量与份量录入不变。
- 仅记录和展示，不提供营养目标、评分或饮食建议。新功能仍须按 [CAL-8 交接说明](CAL8_NUTRITION.md) 独立验证。

## kJ、kcal 与模型

- 固定换算：`1 kcal = 4.184 kJ`。kJ 输入直接保存，kcal 输入先转换为 kJ；备份和 JSON 中的能量仍是 kJ，与当前显示偏好无关。
- 默认体重模型系数为 `32216.8 kJ/kg`，在 kcal 模式下显示等价的 `7700 kcal/kg`。模型是简化预测，不会把预测体重写入实际称重表。
- 运动能量应填写额外运动消耗（Active Calories），不是包含全天基础消耗的总热量，以免重复计入。
- 切换单位不会改变已存能量、模型结果或 Treemap 面积，也不会改变营养克数。营养不反推能量、不参与模型；沿用 CAL-6 的两位小数显示和精度保留控件。

## 启动或数据异常

- 找不到依赖或 DLL：先确认完整解压、没有单独移动 EXE，并核对 Release 的 Windows x64 要求；不要把网上零散 DLL 复制进程序目录。
- 找不到旧数据：检查设置页数据目录、`CALORIEK_DATA_DIR`、命令行参数及 `config.json`。不要把新的空库误认为旧库已被删除。
- 无法备份、迁移或恢复：保留完整错误信息，检查磁盘空间、目录写权限，以及是否有其他 CalorieK/SQLite 工具正在使用该库。
- 提交问题时说明 Windows 版本、程序版本（主窗口标题）和错误文本；截图与日志先去掉健康数据、姓名和个人路径。不要公开上传整个数据库、备份或 handoff ZIP。
